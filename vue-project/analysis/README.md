# 安牌シミュレーターの当たり率計測

天鳳鳳凰卓の牌譜を使って、アプリの色分け（`src/helpers/waits.ts` の `get_tile_statuses`）が
どれくらい当たりを見分けられているかを計測し、HTMLのレポートにまとめる。
ローカルで実行するだけで、結果はアプリに組み込まない。

## 計測すること

### 1. 色ごとの当たり率

「その色の牌を切ったら、リーチ者に当たる確率」。

- **対象の場面**: リーチ者がちょうど1人いる局で、リーチが成立した（`reach_accepted`）後に、
  ほかの3人のうち誰かが牌を切る直前。2人目のリーチが成立した後の場面は数えない。
- **数える牌**: その人の手牌（鳴いた牌を除く）にある牌の種類。同じ牌を2枚持っていても1回と数える。
  赤5は5として扱う。
- **色の付け方**: その時点のリーチ者の捨て牌（鳴かれた牌も含む）を使う。

  | 行 | 決め方 |
  |---|---|
  | 現物 | リーチ者が捨てた牌（数牌・字牌とも） |
  | 濃い青 | `get_tile_statuses` が `safe` |
  | 薄い青 | `likely_safe` |
  | 薄い赤 | `caution` |
  | 濃い赤 | `danger` |
  | 無地 | `default`（リーチ者がその種類の数牌を1枚も捨てていない） |
  | 字牌 | 現物でない字牌 |

  数牌は種類（萬子・筒子・索子）ごとに、リーチ者のその種類の捨て牌の番号を `get_tile_statuses` に渡す。
  アプリの判定関数をそのまま import して使い、計測用に書き直さない。
- **当たりの判定**: その牌がリーチ者の待ちに入っていて、かつリーチ者がフリテンでなければ当たり。
  - 待ちは、リーチ成立時のリーチ者の手牌から計算する（通常の形・七対子・国士無双）。暗槓の後は計算し直す。
  - フリテンは、リーチ者の捨て牌に待ち牌がある場合と、リーチ成立後に他家が切った待ち牌でロンしなかった場合。
  - リーチは役があるので、待ち牌が出たらロンできるものとする。
- **当たり率** = 当たり ÷ 母数。行ごとに母数・当たり・当たり率を出す。

### 2. シミュレーターに従って切ったときの振込率

「1の表で当たり率が低い行から順に、手にある一番安全な行の牌を切ったら、その1打で振り込む確率」。

- 切る順番は、こちらで決め打ちせず1の結果で決める（無地を薄い赤より先に切るべきかも、この順番に出る）。
- 同じ行の牌が手に複数あるときは、どれを切るか決まらないので平均をとる。
  例: 一番安全な行の牌が2種類あって1種類が当たりなら、その1打は0.5回の振り込みと数える。
- シミュレーター通りに切ると、その後の手牌が牌譜と変わる。そのため出せるのは1打ごとの振込率だけで、
  局が終わるまで降り続けたときの振込率は出さない。
- あわせて、どの行の牌を切ることになったかの割合を出す（例: 安全な牌がなく薄い赤を切らされた割合）。

### 3. 集計の確認

結果を信じてよいかを確かめるため、レポートに次の数を出す。

- 対象の場面で、牌譜でリーチ者が他家からロンした牌のうち、こちらの判定が「当たり」でなかった数（0になるはず）。
  待ちの計算とフリテン判定を、実際のロンで照合する。
- 対象の場面で他家が実際に切った牌のうち、こちらの判定は「当たり」なのにロンされなかった数（見逃し。ほぼ0のはず）。
- 待ちが計算できなかった（聴牌していない）リーチの数（0になるはず）。
- 読み込めずに飛ばした牌譜の数。

## レポート（HTML）

1つのHTMLファイルに出力する。牌はアプリと同じ画像（`public/images/{種類}/{色}/{番号}.png`）を
埋め込んで表示するので、ファイル単体でブラウザで開ける。画像フォルダの種類は 1: 索子、2: 萬子、3: 筒子。
字牌は画像がないので、文字（東南西北白發中）を牌の形に描く。

1. **概要**: 使った牌譜（年・半荘数・局数）、対象の場面の数、リーチの数、計測の定義。
2. **色ごとの当たり率**: 行ごとの母数・当たり・当たり率の表と、当たり率の横棒グラフ。
3. **シミュレーターに従って切ったときの振込率**: 使った切る順番、1打ごとの振込率、
   切ることになった行の割合とその行での振込率。
4. **集計の確認**: 上の「集計の確認」の数。
5. **実例**:
   - 行ごと（濃い青・薄い青・薄い赤・濃い赤・無地・字牌）に、その行の牌が当たりだった場面を3件。
   - シミュレーター通りに切ると振り込む場面を3件。
   - 各場面に次を載せる。
     - 天鳳の牌譜へのリンク（`https://tenhou.net/0/?log={牌譜ID}&tw={切る人の席}&ts={局の番号}`）と、局・巡目。
       リンクが正しい局を開くかは実装時に確かめる
     - リーチ者の捨て牌（リーチ宣言牌に印を付ける）
     - リーチ者の手牌と待ち牌（当たり牌）
     - 切る人の手牌（シミュレーターの色で表示）
     - 切る人が実際に切った牌と、シミュレーター通りなら切る牌（当たりかどうか）
   - 実例は固定のシードでランダムに選び、何度実行しても同じ例になるようにする。

## データ

Hugging Face の [nikketryhard/tenhou-houou-mjai](https://huggingface.co/datasets/nikketryhard/tenhou-houou-mjai) にある、
天鳳鳳凰卓の2025年分 `tenhou-houou-2025.tar`（約1.3GB、約20万半荘）を使う。

- tarの中身は、半荘ごとの `{牌譜ID}.mjai.json.zst`（mjai形式のイベントを1行1つ並べたJSONをzstdで圧縮したもの）。
- リポジトリの外（`~/mahjong-data/`）に置く。
- 牌譜の利用は天鳳の規約に従い、ローカルでの集計だけに使う。

```sh
huggingface-cli download nikketryhard/tenhou-houou-mjai tenhou-houou-2025.tar \
  --repo-type dataset --local-dir ~/mahjong-data
```

## 実行方法

```sh
cd vue-project
# まず数千半荘で試す
npm run analyze -- ~/mahjong-data/tenhou-houou-2025.tar --limit 5000
# 1年分すべて
npm run analyze -- ~/mahjong-data/tenhou-houou-2025.tar
```

レポートは `analysis/out/report.html` に出力する（`--out` で変更できる）。`analysis/out/` はgitに含めない。

## 構成

`vue-project/analysis/` に置く。アプリの `src/` とは分け、ビルドには含めない。
TypeScriptを `vite-node`（vitestに含まれている）で実行し、新しいパッケージは追加しない。
tarは自前で読み、zstdの解凍はNode標準の `zlib.zstdDecompressSync` を使う。

| ファイル | 役割 |
|---|---|
| `tiles.ts` | mjaiの牌の表記（`5m`・`5mr`・`E` など）と、34種類の牌の番号の相互変換 |
| `tenpai.ts` | 手牌から待ち牌を求める（通常の形・七対子・国士無双、暗槓あり） |
| `tar.ts` | tarファイルを先頭から読み、牌譜IDと解凍したmjaiのテキストを1半荘ずつ返す |
| `replay.ts` | 1半荘のイベントを再生し、手牌・捨て牌・リーチ・フリテンを追って、対象の場面を1つずつ返す |
| `tally.ts` | 場面ごとに牌に色を付けて当たりを数え、シミュレーターに従ったときの振込率を計算し、実例を選ぶ |
| `report.ts` | 集計結果からHTMLを作る |
| `main.ts` | 引数（tarのパス・`--limit`・`--out`）を読み、上をつないでレポートを書き出す |

`package.json` に `"analyze": "vite-node analysis/main.ts"` を追加する。

## テスト

vitestで次をテストする（`npx vitest run`）。

- `tiles.ts`: 赤5・字牌を含む表記の変換。
- `tenpai.ts`: 両面・嵌張・辺張・単騎・シャンポン・多面張・七対子・国士無双・暗槓ありの待ち。
- `replay.ts`: 手で書いた短いmjaiの局で、対象の場面の取り出し、2人目のリーチ後に数えないこと、
  鳴かれた牌が捨て牌に入ること、リーチ後の見逃しでフリテンになること。
- `tally.ts`: 色の付け方、当たりの判定、同じ行に複数あるときの平均、当たり率の順番での切る牌の選び方。
- `report.ts`: 小さな集計結果からHTMLが作れること（表と実例が含まれること）。

## 割り切り

- 対象はリーチ者1人の場面だけ。ダマ・鳴き手の聴牌・2人以上のリーチは数えない。
- 喰い替えの禁止は考えない（鳴いた直後も手牌のどの牌でも切れるものとする）。
- 槍槓は考えない（数えるのは牌を切る場面だけ）。
- リーチ前の同巡内フリテンは考えない。
- シミュレーターと同じく、壁（見えている枚数）や他家の捨て牌は色に使わない。
- 切る順番は計測と同じデータで決める。行が7つしかなく母数が大きいので、偏りは無視できる。
