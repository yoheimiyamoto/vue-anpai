# 安牌シミュレーターの振込率計測

天鳳鳳凰卓の牌譜を使って、アプリの色分け（`src/helpers/waits.ts` の `get_tile_statuses`）が
色ごとにどれくらい振り込むかを計測し、アプリの /report のページで見られるようにする。
牌譜の読み込みと集計はローカルで行い、アプリには集計した数字（`src/data/report.json`）だけを入れる。

## 計測すること

### 1. 色ごとの振込率

「その色の牌を切ったら、リーチ者に振り込む確率」。実際に切った牌だけでなく、手にある牌すべてを「もし切ったら」で数える。

- **対象の場面**: リーチ者がちょうど1人いる局で、リーチが成立した（`reach_accepted`）後に、
  ほかの3人のうち誰かが牌を切る直前。2人目のリーチが成立した後の場面は数えない。
- **数える牌**: その人の手牌（鳴いた牌を除く）にある牌の種類。同じ牌を2枚持っていても1回と数える。
  赤5は5として扱う。
- **色の付け方**: その時点のリーチ者の捨て牌（鳴かれた牌も含む）を使う。

  | 行 | 決め方 |
  |---|---|
  | 現物 | リーチ者が捨てた牌（数牌・字牌とも） |
  | 濃い青 | `get_tile_statuses` が `safe` |
  | 薄い青 | `likely_safe` |
  | 薄い赤 | `caution` |
  | 濃い赤 | `danger` |
  | 無地 | `default`（リーチ者がその種類の数牌を1枚も捨てていない） |
  | 字牌 | 現物でない字牌 |

  数牌は種類（萬子・筒子・索子）ごとに、リーチ者のその種類の捨て牌の番号を `get_tile_statuses` に渡す。
  アプリの判定関数をそのまま import して使い、計測用に書き直さない。
- **当たりの判定**: その牌がリーチ者の待ちに入っていて、かつリーチ者がフリテンでなければ当たり。
  - 待ちは、リーチ成立時のリーチ者の手牌から計算する（通常の形・七対子・国士無双）。暗槓の後は計算し直す。
  - フリテンは、リーチ者の捨て牌に待ち牌がある場合と、リーチ成立後に他家が切った待ち牌でロンしなかった場合。
  - リーチは役があるので、待ち牌が出たらロンできるものとする。
- **振込率** = 当たりの数（振り込み）÷ 母数。行ごとに母数・振り込み・振込率を出す。

### 2. 集計の確認

結果を信じてよいかを確かめるため、計測を実行したときにターミナルに次の数を出す（レポートのページには載せない）。

- 対象の場面で、牌譜でリーチ者が他家からロンした牌のうち、こちらの判定が「当たり」でなかった数（0になるはず）。
  待ちの計算とフリテン判定を、実際のロンで照合する。
- 対象の場面で他家が実際に切った牌のうち、こちらの判定は「当たり」なのにロンされなかった数（見逃し。オーラスの着順のための見逃しや切断で少数ある）。
- 待ちが計算できなかった（聴牌していない）リーチの数（0になるはず）。
- 読み込めずに飛ばした牌譜の数。

## レポート（/report）

アプリの2つ目のページ（`report/index.html` → `src/report.ts` → `src/ReportPage.vue`）として作る。
Viteの複数ページのビルドで `docs/report/index.html` に出力されるので、公開URLは `/vue-anpai/report/` になる。
ルーターは使わない（GitHub Pagesで /report を直接開いても404にならない）。トップ画面からのリンクは置かない。

1. **概要**: 使った牌譜（ファイル名・半荘数・局数）、リーチの数、対象の場面の数、振込率の定義。
2. **色ごとの振込率**: 行ごとの母数・振り込み・振込率の表と、振込率の横棒（スマホでは横棒を出さない）。
   行の色の見本に、アプリの牌と同じ色の四角を出す。字牌はアプリでも色が付かないので四角を出さない。

トップ画面の理由（`src/components/Reasons.vue`）の末尾にも、その理由の色の振込率を「（4.3%）」の形で、数字だけ出す。理由は振込率の低い順に並べる。
数字は同じ `src/data/report.json` を使う（理由の色 safe・likely_safe・caution・danger を、濃い青・薄い青・薄い赤・濃い赤の行に対応させる）。

## データ

Hugging Face の [nikketryhard/tenhou-houou-mjai](https://huggingface.co/datasets/nikketryhard/tenhou-houou-mjai) にある、
天鳳鳳凰卓の2025年分 `tenhou-houou-2025.tar`（約1.3GB、約20万半荘）を使う。

- tarの中身は、半荘ごとの `{牌譜ID}.mjai.json.zst`（mjai形式のイベントを1行1つ並べたJSONをzstdで圧縮したもの）。
- リポジトリの外（`~/mahjong-data/`）に置く。
- 牌譜の利用は天鳳の規約に従う。牌譜そのものはリポジトリにもアプリにも入れず、集計した数字だけを入れる。

```sh
huggingface-cli download nikketryhard/tenhou-houou-mjai tenhou-houou-2025.tar \
  --repo-type dataset --local-dir ~/mahjong-data
```

## 実行方法

```sh
cd vue-project
# まず数千半荘で試す
npm run analyze -- ~/mahjong-data/tenhou-houou-2025.tar --limit 5000
# 1年分すべて
npm run analyze -- ~/mahjong-data/tenhou-houou-2025.tar
```

集計結果は `src/data/report.json` に書き出す（`--out` で変更できる）。このJSONはコミットする。

```sh
# 手元で見る（http://localhost:5173/vue-anpai/report/）
npm run dev
# 公開用にビルドする（docs/ に出力。main に push すると GitHub Pages に反映される）
npm run build
```

## 構成

計測は `vue-project/analysis/` に置く。アプリの `src/` とは分け、ビルドには含めない。
TypeScriptを `vite-node`（vitestに含まれている）で実行し、新しいパッケージは追加しない。
tarは自前で読み、zstdの解凍はNode標準の `zlib.zstdDecompressSync` を使う。

| ファイル | 役割 |
|---|---|
| `tiles.ts` | mjaiの牌の表記（`5m`・`5mr`・`E` など）と、34種類の牌の番号の相互変換 |
| `tenpai.ts` | 手牌から待ち牌を求める（通常の形・七対子・国士無双、暗槓あり） |
| `tar.ts` | tarファイルを先頭から読み、牌譜IDと解凍したmjaiのテキストを1半荘ずつ返す |
| `replay.ts` | 1半荘のイベントを再生し、手牌・捨て牌・リーチ・フリテンを追って、対象の場面を1つずつ返す |
| `tally.ts` | 場面ごとに牌に色を付けて、行ごとの母数と振り込みを数える |
| `main.ts` | 引数（tarのパス・`--limit`・`--out`）を読み、上をつないで `src/data/report.json` を書き出す |

`package.json` に `"analyze": "vite-node analysis/main.ts --"` を追加する（vite-node は `--` の後ろの引数をスクリプトに渡す）。
Node は v23.9 以上が必要（`zlib.zstdDecompressSync` を使う）。

レポートのページは次のファイルで作る。

| ファイル | 役割 |
|---|---|
| `report/index.html` | 2つ目のページのHTML（`vite.config.ts` の `build.rollupOptions.input` に追加） |
| `src/report.ts` | ページの入口 |
| `src/ReportPage.vue` | 概要と色ごとの振込率の表 |
| `src/helpers/report.ts` | 集計結果の型、振込率の表示、横棒の長さ、行と色の対応 |
| `src/data/report.json` | 計測スクリプトが書き出す集計結果 |

## テスト

vitestで次をテストする（`npx vitest run`）。

- `tiles.ts`: 赤5・字牌を含む表記の変換。
- `tenpai.ts`: 両面・嵌張・辺張・単騎・シャンポン・多面張・七対子・国士無双・暗槓ありの待ち。
- `replay.ts`: 手で書いた短いmjaiの局で、対象の場面の取り出し、2人目のリーチ後に数えないこと、
  鳴かれた牌が捨て牌に入ること、リーチ後の見逃しでフリテンになること。
- `tally.ts`: 色の付け方、当たりの判定、行ごとの数え方、ロンとの照合。
- `src/helpers/report.ts`: 振込率の表示（母数0は「-」）、横棒の長さ（NaNにならないこと）、行と色の対応、理由の色ごとの振込率、理由の並び順。

## 割り切り

- 対象はリーチ者1人の場面だけ。ダマ・鳴き手の聴牌・2人以上のリーチは数えない。
- 喰い替えの禁止は考えない（鳴いた直後も手牌のどの牌でも切れるものとする）。
- 槍槓は考えない（数えるのは牌を切る場面だけ）。
- リーチ前の同巡内フリテンは考えない。
- シミュレーターと同じく、壁（見えている枚数）や他家の捨て牌は色に使わない。
